# Правила автоматичних перевірок (check_chapter.py, brick_status.py)

Кожне правило має фіксований код, який цитують інші частини скіла. Колонка «Вимога» містить коди вимог (`R-…`) з `requirements.md`. Усі перевірки евристичні: вони знаходять кандидатів на помилку, а рішення
ухвалює рецензування за SKILL.md. Серйозність: ERROR — порушено вимогу, виправити до подання; WARN — імовірна проблема
або типове зауваження опонента; INFO — факт або нагадування для ручної перевірки.

Формат рядка: `ERROR S01 [розділ 2] повідомлення`; у дужках — розташування: `заголовок/номер підрозділу, п.<номер абзацу>: «перші 80 знаків»`.
Підсумок: `SUMMARY: E error(s), W warning(s), I info`. Код виходу: 1 — є ERROR, 2 — вхід не прочитано, інакше 0.

## Модель входу

1. Формати: `.md`, `.txt` (зокрема `pdftotext -layout`), `.docx` (python-docx: стилі `Heading N` / `Заголовок N` -> `#`, клітинки таблиці з'єднуються ` | `, підписи — звичайні абзаци). `.pdf` -> exit 2 з підказкою `pdftotext -layout`.
2. Вид частини (`--kind`, інакше за першим заголовком): `anotatsiia`, `vstup`, `rozdil` (N з «РОЗДІЛ N», `# N.`, `N.M` або «Висновки до розділу N», чи `--chapter N`), `vysnovky`, `spysok`, `dodatky`, `poznachennia`, `zmist`. Якщо заголовок не розпізнано — підказка за назвою файлу (`rozdil-2`, `vstup`, …).
3. Файл із кількома частинами верхнього рівня (уся дисертація) розбивається автоматично (вимкнути: `--no-split` або `--kind`). Зміст (ЗМІСТ) пропускається.
4. Обсяг: `сторінки = знаки з пробілами / 1800` (`CHARS_PER_PAGE`, `--chars-per-page`); TNR 14, інтервал 1,5, A4, поля 20–25 мм.
5. Нумерований заголовок у `.docx` з автонумерацією не містить номера в тексті — перевірки S02/F02 для нього мовчать.

## check_chapter.py

### Структура

| Код | Серйозність | Що спрацьовує | Чого не вміє | Вимога |
|---|---|---|---|---|
| S00 | INFO | вид частини не визначено | — | — |
| S01 | ERROR / WARN / INFO | розділ без заголовка «Висновки до розділу N» або висновки не останні (ERROR); заголовок іншого розділу (ERROR); заголовок не за формою («Висновок до розділу», просто «Висновки») — WARN; без номера — INFO | не оцінює зміст висновків | R-STR-11 |
| S02 | ERROR | номер підрозділу не починається з номера розділу; пропуск (2.1, 2.3); дублікат; рівень 3 під чужим рівнем 2 | потребує номера в тексті заголовка; працює лише коли номер розділу відомий | R-FMT-06 |
| S03 | WARN | розділ 1 без підрозділу з «постановка / завдання дослідження / формулювання» в назві | не перевіряє, чи постановка змістовна | R-STR-12, R-FAIL-04 |
| S04 | INFO (WARN при < 50 % або > 200 %) | орієнтовний обсяг vs типовий: вступ 8–12, розділ 1 15–25, розділи 2+ 25–50, висновки 2–5, анотація 2–4 на мову | оцінка за знаками, рисунки й формули не враховано | R-STR-16 |
| S05 | WARN | нумерований заголовок має рівно один підпункт (2.3.1 без 2.3.2) | — | R-FMT-06 |

### Рисунки, таблиці, формули

| Код | Серйозність | Що спрацьовує | Чого не вміє | Вимога |
|---|---|---|---|---|
| F01 | ERROR / WARN | посилання `рис. 2.3` без підпису «Рисунок 2.3» у цій частині (ERROR; чужі розділи пропускаються); підпис, на який немає посилання (WARN); дубль підпису (WARN) | не бачить посилань з інших файлів; рисунки-картинки без підпису лише рахуються (F05) | R-FMT-09, R-FMT-12 |
| F02 | ERROR | номер підпису рисунка/таблиці або формули не починається з номера розділу | лише коли розділ відомий; додатки (А.1) пропускаються | R-FMT-07, R-FMT-09 |
| F03 | WARN | підпис таблиці без посилання; посилання на таблицю без підпису | аналогічно F01 | R-FMT-11 |
| F04 | WARN | номери формул розділу не йдуть підряд з 1 (виводить послідовність) | формули-картинки без номера в тексті не видно; номер упізнається лише в кінці рядка `(2.3)` або `\tag{2.3}` | R-FMT-07 |
| F05 | INFO | підпис не у формі «Рисунок N.M – Назва» / «Таблиця N.M – Назва» (довге тире, без крапки в кінці); зображення без підпису | — | R-FMT-10, R-FMT-11 |

### Джерела

| Код | Серйозність | Що спрацьовує | Чого не вміє | Вимога |
|---|---|---|---|---|
| C01 | WARN / INFO | розділ 1: менше одного посилання на сторінку або жодного (WARN); інший розділ без посилань (INFO) | не оцінює релевантність джерел | R-FMT-12, R-STR-10 |
| C02 | WARN | `--first-citation-order`: нове джерело не дорівнює «найбільше раніше + 1» (`--ref-start` — перший номер частини); `--max-ref N`: посилання понад N | порядок першої згадки перевіряється лише в межах файлу | R-FMT-14, R-FMT-15 |
| C03 | INFO | одночасно `[n]` і `(Автор, рік)` | — | R-FMT-14 |

Розбір посилань: `[12]`, `[3, 7]`, `[1–5]`, `[12, с. 40]`; `[N %]`, `[текст]` посиланнями не вважаються.

### Новизна й зміст

| Код | Серйозність | Що спрацьовує | Чого не вміє | Вимога |
|---|---|---|---|---|
| N01 | ERROR / WARN | у вступі немає блоку «Наукова новизна» (ERROR); у блоку (вступ, анотація, висновки) є пункти без маркера градації `вперше / удосконалено / набуло подальшого розвитку` (ERROR); в анотації/висновках немає ні блоку, ні жодного маркера (WARN) | пункти прози групуються за маркером: речення без маркера вважається продовженням попереднього | R-INTRO-08, R-NOV-03 |
| N02 | WARN | пункт новизни (вступ, анотація) без відмінності (`відрізняється / на відміну від / полягає / за рахунок`) або без ефекту (`дозволило / забезпечує / підвищує / зменшує …`) | не оцінює, чи твердження істинне | R-NOV-04, R-FAIL-01 |
| N03 | WARN | розділ N ≥ 2 без жодного речення з маркером градації (абзац-новизна) | — | R-NOV-08 |
| N04 | ERROR / WARN | у вступі немає обов'язкових блоків: актуальність; зв'язок з програмами/темами (НДР); мета; завдання; об'єкт; предмет; методи; наукова новизна; практичне значення; особистий внесок; апробація; публікації; структура та обсяг (ERROR, список). Немає опису розділів «У першому розділі …» (WARN) | блоки впізнаються за ключовим словом на початку абзацу/речення | R-INTRO-01…13 |
| N05 | WARN | речення «Об'єкт дослідження є …» без «процес/процеси» | не відрізняє об'єкт від предмета за змістом | R-INTRO-05, R-121-01 |
| N06 | WARN | мета починається з інфінітива (розробити/створити/дослідити) замість іменника результату (підвищення/зменшення/забезпечення/скорочення) | — | R-INTRO-03 |
| N07 | WARN | завдання, що починаються не з інфінітива (виводить перелік) | не розрізняє доконаний/недоконаний вид; перелік береться зі списку або з рядка «1) …; 2) …» | R-INTRO-04 |
| N08 | INFO | розділ N ≥ 2: менше 2 влучень SE_RE (лексика програмної інженерії) на 1000 слів — «перевірте відповідність 121» | словникова евристика | R-121-01, R-121-05, R-FAIL-05 |
| N09 | WARN | жоден пункт новизни у вступі не містить «архітектур» (практика КПІ 121: один із результатів — архітектура ПЗ) | — | R-121-07, R-NORM-11 |

## brick_status.py

| Код | Серйозність | Що спрацьовує | Чого не вміє | Вимога |
|---|---|---|---|---|
| B01 | ERROR / WARN / INFO | положення новизни (вступ, анотація, загальні висновки, висновки розділів, за наявності — `--novelty`) мають збігатися дослівно (після нормалізації пробілів і регістру). ## Наслідки для автора

1. ERROR не можна залишати: їх знімають виправленням тексту, а не вимкненням перевірки.
2. WARN потребує або виправлення, або свідомого рішення (зафіксувати в нотатках до розділу).
3. INFO не блокують, але L03 дає чернетку «Переліку умовних позначень», а S04/B04 — орієнтири обсягу.
